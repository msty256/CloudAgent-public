## 4. 我实测过的 sql 域断言结果（P1 的直接依据）

用只读角色对 14 道 sql 题逐条跑过 `EXPLAIN` / `pg_indexes`，结论：

| 题 | 断言 | 当前库上是否成立 |
|---|---|---|
| sql-001 | `Seq Scan on orders` + `tenant_id` 无索引 | ✅ |
| sql-002 | `Seq Scan on orders` + `created_at` 无索引 | ✅ |
| sql-003 | `Bitmap Index Scan on idx_customers_region` + 索引存在 | ✅ |
| sql-004 | `Filter: (lower(region)` + 索引存在 | ✅ |
| sql-005 | `Index Scan using orders_pkey` | ✅ |
| sql-006 | `Hash Join` + `customer_id` 无索引 | ✅ |
| sql-007 | `Sort Key: amount DESC` | ✅ |
| sql-008 | `Seq Scan on orders` + `status` 无索引 | ✅ |
| sql-009 | `date(created_at)` + `created_at` 无索引 | ✅ |
| sql-013 | `get_lock_info` 被调用且当前无等待锁 | ✅（实测 `waiting: []`） |
| sql-014 | `get_table_stats` 的 `n_live_tup=2000` / `region_n_distinct=4` + 计划含 `on customers` | ✅（实测 2000 / 4.0） |
| sql-010 | 历史锁等待不可回溯 | ⚠️ 不是数据问题，是**工具能力边界** |
| sql-011 | 数据库不可用时的降级 | ⚠️ 需要"DSN 不可达"这一特定环境 |
| sql-012 | 输入不足时请求补充 | ⚠️ 与数据无关，属协议行为 |

**所以 P1 不是"造数据"，是"把已在库里的数据变成仓库内可复现的 seed + 可执行断言"。**
