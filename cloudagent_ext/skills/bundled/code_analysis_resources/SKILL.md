# Code Analysis Skill（代码诊断方法论）

用于代码相关故障的诊断：调用链断裂、异常传播、变更引入的可疑点、空指针/并发/资源管理问题。**只读分析，不修改代码。**

## 1. 触发条件

- 用户报告"这次提交/这次改动引入了什么问题"；
- 接口/任务报错，怀疑出在代码逻辑（非 SQL、非日志层面可独立解释）；
- 需要还原某功能从入口到出口的调用链与异常路径。

不适用：纯 SQL 性能问题（sql-optimization）、纯日志事件链问题（log-analysis）、代码评审/风格建议（code-reviewer）。

## 2. 输入充分性检查

- 有无具体症状（报错信息/异常类型/触发条件/影响范围）？没有则先收集；
- 有无可疑的变更范围（commit/diff/文件）？没有则按症状反推（入口 → 调用点 → 可疑分支）；
- 有无运行证据（日志/堆栈/监控）？没有则结论只能到 `suspected`。

## 3. 证据规范

- 每个结论必须挂 `file:line`（必要时附 diff 片段/符号名）；
- 引用符号必须来自 `find_symbol`/`find_references` 或 `Read` 的实际返回，不得凭记忆编造；
- `find_references` 的结果必须声明其边界：同名不区分作用域、`getattr` 字符串与装饰器引用不覆盖、可能因扫描截断漏检；
- 证据不足时明确列出"观测不到/无法确认"清单，不得用推断填补。

## 4. 分析流程

1. **范围界定**：确定可疑文件/包/变更范围（`path`/`include` 缩小扫描）；
2. **符号定位**：`find_symbol` 找定义，`find_references` 找调用点（记住边界）；
3. **调用链重建**：从入口到症状点逐层列出 调用方 → 被调方（file:line）；
4. **异常路径**：异常捕获/吞掉/重抛、错误码转换、资源释放（with/finally/close）；
5. **静态风险分级**（见第 5 节）；
6. **证据缺口**：列出无法确认的部分与建议的补证方式。

## 5. 静态风险分级（本 Skill 的核心约束）

每个风险项必须标注 `risk_level`：

- **`suspected`（静态可疑）**：证据仅来自代码阅读/符号关系——**允许**的表述："疑似/可能/候选/需验证"；
- **`confirmed`（已确认）**：有运行证据（异常堆栈、日志、复现）——才允许"已确认/发生"。

**红线：`suspected` 不得表述为"已发生/已导致/已引起/已造成"。** 静态风险只是"可能存在缺陷"，不是"已经发生的故障"。

## 6. 输出契约

- `next_steps`：每条必须是**一个能用一次委派回答的、针对具体证据缺口的命题**（如「orders 同步任务是否被触发」）；不得写「建议增加监控」这类非取证项；无待查项时留空数组。
- `evidence` 可选语义字段：`proves`（这条证据直接证明的一句话，≤120 字）/ `cannot_prove` / `applicability`（成立条件，如 `{"window": "2026-10-22T09:00"}`）/ `relation`（与其它证据的关系）；`observation` 仍须写全可核验事实，`proves` 是它的浓缩而不是替代；`scope` 记“查了多大范围”，`applicability` 记“结论在什么条件下成立”。

按统一诊断结果协议（`DiagnosisResult`）输出：

- `summary`：症状 → 最可能位置（file:line）→ 风险等级；
- `root_causes[]`：`description` + `match_terms` + `severity`（每项注明 suspected/confirmed）；
- `required_evidence[]`：已采集（符号/引用/文件）与缺失证据；
- `limitations`：`find_references` 边界、扫描截断、未执行代码等；
- 证据 id 使用 `ev:code:<seq>`（**域由命名空间前缀体现**），`refs` 形如 `path:line`。

## 7. 工具使用规范

| 用途 | 工具 | 说明 |
|---|---|---|
| 找定义 | `find_symbol` | 精确名匹配；签名超 200 字符截断 |
| 找调用点 | `find_references` | 字面名匹配；同名不区分作用域；getattr/装饰器不覆盖 |
| 读文件 | `Read` | 读上下文，确认证据 |
| 搜文本 | `Grep` | 正则检索（日志/配置/字符串常量） |
| 看历史变更 | `Bash(git diff)` / `Bash(git log)` | 只读子命令；不得执行构建/测试 |

- **禁止**执行目标代码（不 import/exec/eval，不跑测试/脚本）；
- 不重复调用相同输入；证据应形成链（定义 → 调用点 → 上下文）。
- 扫描截断（`truncated=true`）时，必须用 `path`/`include` 缩小范围重查，不得把截断结果当全量。

## 8. 分析深度与停止条件

- 调用链追到入口或框架边界即可停止（不无限回溯）；
- 同一结论证据重复 3 次以上无新增信息 → 停止并声明；
- 证据不足时如实降级（`partial`/`failed`），不得编造根因。

## 9. 红线（违反即结论无效）

1. 静态风险表述为"已发生/已导致/已引起"；
2. 未运行任何代码却声称"已复现/已验证"；
3. 引用不存在的符号或编造 file:line；
4. 修改源码（本 Skill 只读）；
5. 把 `find_references` 当作精确引用分析（忽略其边界声明）。
