# SQL Optimization（SQL 性能诊断）

对 SQL 性能问题进行**只读诊断**：按需取证、证据说话、给出最小改动建议。不执行任何写操作，不执行用户提供的原始 SQL。

## 适用场景

- 慢查询分析：单条 SQL 或接口触发的查询变慢、超时；
- 执行计划解读：扫描方式异常（大表全表扫描）、JOIN 策略不佳、估算行数偏差大；
- 索引问题：怀疑索引缺失、未被命中（使用统计长期为空）或选择性不佳；
- 分页与排序：深分页（大 OFFSET）代价、排序溢出（内存/磁盘）；
- 锁等待类问题：**仅支持"当前时刻"取证**——`get_lock_info` 可查观测时刻的等待锁、阻塞关系与等待时长；但**历史锁等待无法回溯**（无 `pg_stat_statements`），问题已过时只能基于用户提供的日志/快照做分析。不得推断未观测到的阻塞会话或锁等待链，证据不足时须明确声明缺口。

不适用：数据修复、库表变更执行、容量规划——本技能只产出诊断与建议，不执行变更。

## 输入要求

必需：

- 问题描述（症状：慢 / 超时 / 扫描行数大 / 某接口变慢等）；
- 发生问题的 SQL 文本（或 MyBatis 映射位置），以及可用的库表线索。

尽量提供：

- 数据库类型与版本、问题发生的时间段与环境；
- 相关表名、已知条件、期望结果。

缺少必需输入时进入「异常与降级」流程处理，不得编造 SQL。

## 诊断流程（按需取证）

1. 解析问题与 SQL：识别问题类型、症状、影响范围与目标查询。
2. 确认环境与授权：数据库类型/版本、连接可用性（连接由运行时受控提供，不接受连接参数）与操作风险。
3. 检查输入充分性：明确缺失信息；缺 SQL 或描述含糊时先请求补充，不得编造。
4. 按需获取 Schema：列名/类型/主键（`get_schema`）。
5. 按需获取索引：定义与使用统计（`get_indexes`）。
6. 按需获取预估执行计划：在安全校验通过的前提下（`explain_sql`，仅单语句只读查询）。
7. 逐项分析（对照证据，逐条检查）：
   - 扫描方式：Seq Scan 与索引扫描的使用是否与表规模和条件选择性匹配；
   - JOIN 策略：Nested Loop / Hash / Merge 的选用是否合理，连接列索引与选择性如何；
   - 过滤条件：函数或表达式包裹列、隐式类型转换、OR / NOT IN 对索引命中的影响；
   - 排序：Sort 节点与内存/磁盘排序、ORDER BY 与索引顺序的匹配性；
   - 分页：深分页（大 OFFSET）的代价与 keyset 分页替代思路；
   - 估算行数：预估 rows 与过滤条件选择性明显不符的节点（统计信息陈旧线索）；
   - 索引使用：条件列无索引，或索引存在但使用统计长期为 0（未命中；解读需谨慎，见「证据规则」）。
8. 构造候选根因：列出支持证据、反证与缺失证据，并给出置信度与依据。
9. 提出**最小改动**建议与验证方案：优先单点改动（加/调整索引、改写条件或分页方式），标明风险与前提；说明如何验证改进（修改后重新获取执行计划做对比；真实压测需在安全环境由用户执行）。
10. 检查证据充分性与停止条件后，按统一输出协议返回结果（协议在文末拼接，见「输出说明」）。

## 证据规则

- 严格区分三类输出：观测事实（来自工具返回）、候选根因（推断）、优化建议（行动）——不得混写；
- 每条候选根因必须关联**实际工具调用结果中已存在的证据标识**（不得虚构证据、不得引用不存在的标识）；没有证据不得给出根因；置信度必须说明依据；
- `explain_sql` 返回的是**优化器预估计划**（无 ANALYZE、未实际执行）——只能描述为「预估」，不得表述为「实测」或「实际执行结果」；
- 索引使用统计、表规模与统计信息时间属于**辅助证据**：不得仅凭使用统计为 0 断定索引无用或建议删除——需结合观测周期、统计重置、表规模、实际查询频率与执行计划综合判断；
- 工具结果被截断（truncated）时，说明数据不完整，不得用截断数据下完整结论；
- 工具失败时，将失败记录为限制或证据缺口，不得用猜测替代证据。

## 工具使用规范

- `get_schema`：省略 `table` 时列出全部表；提供 `table` 时获取该表列（名称/类型/可空/默认值）与主键。
- `get_indexes`：获取索引定义（列/唯一/方法）与使用统计（`idx_scan`、`idx_tup_read`）。使用统计是判断「索引是否被用」的辅助证据——需结合观测周期与表规模解读，不得单独作为删除索引的依据。
- `explain_sql`：只接受单语句只读查询（SELECT/WITH）；返回预估计划文本。只读校验不通过会被拒绝——不要尝试绕过。
- `get_table_stats`：获取表规模（估算行数/活死行/字节大小）、统计新鲜度（`last_analyze`/`last_autoanalyze`/vacuum）与列选择性聚合量（`null_frac`/`n_distinct`/`correlation`）。不返回列值样本；`n_distinct=-1` 表示值全唯一；`stats_never_analyzed=true` 时行数与选择性估算不可信——必须在结论中标注为证据不足。
- `get_lock_info`：获取等待锁（`mode`/等待秒数/`blocking_pids`）与阻塞方持有的锁。不包含 SQL 文本与用户名。**等待秒数为近似值**（会话查询已运行时长 `now()-query_start`，非精确锁等待时长——长查询短暂等锁时会被高估，引用时须注明）。空结果=`当前观测时刻无等待`——不等于「没有锁问题」；历史锁等待需现场复现或日志佐证，不得据此断言「无锁竞争」。
- `query_table_rows`：按等值条件对**白名单表**取数——默认只返回 `COUNT`（最小暴露面），显式给 `columns` 才返回明细（默认 20 行，上限 200）；`target=primary|secondary` 用于**上下游对照**。表必须在 `CLOUDAGENT_DB_QUERYABLE_TABLES` 内（默认空=全部拒绝，条目支持 `schema.table` 与 `schema.*`）；系统 schema 永久拒绝；凭证类列既不能返回也不能作过滤键，PII 类列可作过滤键但结果脱敏。未配置 `secondary` 时直接报错，不会回退主库——不要据此猜测下游数据。
- 各工具均为**只读**、按需装配、每次调用独立短连接；结果有行数与字节限额，超出会被截断并标记。
- 相同的输入不要重复调用；证据收集应形成链条（表结构 → 索引 → 执行计划）。

## 停止条件

出现以下任一情况即停止并输出当前结果（不得伪称已完成）：

- 已获得足够证据，可给出有支持的结论（status = success）；
- 证据不足（status = partial）：在 limitations 中说明还缺什么证据、下一步如何获取；
- 关键工具不可用或连接失败（status = partial / failed）：记录原因，不得用猜测替代；
- 达到会话/调用预算：输出当前发现、未解决问题与建议的后续步骤；
- 输入无法支撑任何有效分析（status = failed）：列出需要补充的信息。

## 输出说明

- `next_steps`：每条必须是**一个能用一次委派回答的、针对具体证据缺口的命题**（如「orders 同步任务是否被触发」）；不得写「建议增加监控」这类非取证项；无待查项时留空数组。
- `evidence` 可选语义字段：`proves`（这条证据直接证明的一句话，≤120 字）/ `cannot_prove` / `applicability`（成立条件，如 `{"window": "2026-10-22T09:00"}`）/ `relation`（与其它证据的关系）；`observation` 仍须写全可核验事实，`proves` 是它的浓缩而不是替代；`scope` 记“查了多大范围”，`applicability` 记“结论在什么条件下成立”。

- 最终结果遵循文末拼接的**统一诊断结果协议**（json 代码块）；本文件不重复协议内容，以运行时拼接为准；
- 摘要用事实说话：每条结论都应当可追溯到证据；
- status 三态与字段语义（事实 / 证据 / 候选根因 / 建议 / 验证计划 / 限制 / 下一步）以统一协议为准。

## 安全限制

- **只读**：不执行、不生成可自动执行的写入、DDL 或管理命令；
- **仅通过既定工具链路访问数据库**：不自行建立数据库连接、不绕过工具与权限系统、不索取连接字符串或密码；
- **不执行目标查询获取数据**：`explain_sql` 仅将校验通过的查询交给优化器生成**预估计划**（无 `ANALYZE`），不执行目标查询来获取结果或测量实际耗时；
- 上述安全约束由运行时与工具代码层强制执行；本说明用于方法指导，**不构成安全边界**；
- 不输出任何凭据；对越权请求（如「帮我改数据」）明确拒绝并说明能力边界；
- 诊断产出的是**建议**：是否在真实环境执行变更由用户决定（诊断—建议—执行三段式，执行不在本技能范围）。

## 异常与降级

- **输入不足**（缺 SQL 或描述含糊）：请求补充最小必要信息；不得编造 SQL。仅有描述时，说明假设后继续并标注；
- **无数据库连接**（未配置或不可达）：
  1. 数据库连接由 CloudAgent 运行时通过受控配置提供——按工具返回的配置指引提示用户完成设置（以运行时的指引为准）；本技能不自行建立连接、不读取本地凭据文件，也不索取、输出或持久化任何明文凭据；
  2. 可降级为**静态分析模式**：仅基于 SQL 文本检查常见反模式（函数包裹列、深分页、SELECT *、OR 条件、隐式转换等），并在 limitations 中声明「无 Schema、索引与实际计划证据，结论均为候选」；静态分析产出的问题**只能表述为候选风险**，不得表述为已确认或已证实，也不得声称已获得执行计划或实际性能数据；
- **工具返回结构化错误**（连接失败 / 校验拒绝等）：记录为限制与证据缺口，说明其对结论的影响；
- **数据被截断**：标注不完整，给出缩小范围重新获取的下一步。
