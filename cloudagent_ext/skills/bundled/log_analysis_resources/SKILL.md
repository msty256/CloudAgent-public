# Log Analysis Skill（日志诊断方法论）

用于日志类故障的诊断：从应用/任务日志中重建事件链、定位最早失败点、关联 Trace。**只读分析，不修改日志。**

## 1. 触发条件

- 用户报告接口/任务失败并给出日志片段或日志目录；
- 需要还原一次请求/任务跨服务的事件顺序；
- 需要从异常堆栈定位最早失败点与传播路径。

不适用：代码逻辑分析（code-analysis）、SQL 性能问题（sql-optimization）、日志聚合/监控查询。

## 2. 输入充分性检查

- 日志范围（服务/时间窗）是否明确？模糊时先按关键字+时间窗缩小；
- 是否有 traceId/Request ID？有则用 `correlate_events` 直接关联；没有则用关键字检索；
- 日志是否有缺失/采样/时间偏差？先确认再下结论。

## 3. 证据规范

- 每个结论必须挂 `file:line`；引用行号必须来自工具返回的实际行；
- 异常栈必须用 `parse_stack_trace` 解析后的结构化结果引用（异常类型/消息/帧/Caused by），不得凭印象描述；
- **续行（`\tat`/`Caused by:`）继承上一条记录行的时间/级别/服务**（`continuation=true`）——引用时须注明；
- 日志缺失、采样、时间偏差必须列入 `limitations`。

## 4. 分析流程

1. **范围确认（必做，先读可搜范围）**：先调 `search_logs`（不带过滤，或 `limit=1`）读取 payload 中的 `log_root` / `available_files`；
   - `scope_empty`（`available_files` 为空）→ **报告配置问题**（`CLOUDAGENT_LOG_ROOT` 未指向有效日志目录），不得编造结论；
   - `no_match_in_scope`（有文件但未命中）→ 放宽关键字/时间窗再试，不得断言"日志里没有"；
   - 范围非空 → 用**真实存在的文件路径**（`file` 子串过滤）与时间窗继续检索；
2. **事件链**：有 traceId → `correlate_events`；无 → 关键字 + 时间窗检索；
3. **首异常定位**：按时间排序找**最早的 ERROR/FATAL**（注意不是"最显眼的异常"）；
4. **栈解析**：对首异常所在行 `parse_stack_trace`，收集帧与 `Caused by` 链；
5. **传播路径**：从首异常服务向调用方追溯（级联异常）；
6. **缺口声明**：缺失服务/时间窗断档/采样 → `limitations`。

## 5. 首异常 ≠ 根因（本 Skill 的核心约束）

- **首异常**只表示"最早观测到的失败点"；
- **根因**需要额外证据：代码路径（可建议主 Agent 派发 code-diagnosis）、配置、数据状态；
- 禁止把首异常的**直接原因**直接表述为**根因**。

## 6. 输出契约

- `next_steps`：每条必须是**一个能用一次委派回答的、针对具体证据缺口的命题**（如「orders 同步任务是否被触发」）；不得写「建议增加监控」这类非取证项；无待查项时留空数组。
- `evidence` 可选语义字段：`proves`（这条证据直接证明的一句话，≤120 字）/ `cannot_prove` / `applicability`（成立条件，如 `{"window": "2026-10-22T09:00"}`）/ `relation`（与其它证据的关系）；`observation` 仍须写全可核验事实，`proves` 是它的浓缩而不是替代；`scope` 记“查了多大范围”，`applicability` 记“结论在什么条件下成立”。

按统一诊断结果协议（`DiagnosisResult`）：

- `summary`：时间窗/服务范围 → 首异常位置（file:line）→ 可能根因（标注证据强度）；
- `root_causes[]`：`description` + `match_terms` + `severity`；
- `required_evidence[]`：已采集（日志行/栈/事件链）与缺失证据；
- `limitations`：日志缺失/采样/时间偏差/续行继承等；
- 证据 id 使用 `ev:log:<seq>`（**域由命名空间前缀体现**），`refs` 形如 `path:line`。

## 7. 工具使用规范

| 用途 | 工具 | 说明 |
|---|---|---|
| 检索 | `search_logs` | 时间窗按 datetime 比较；续行计入并标 `continuation`；`file` 为路径子串过滤（**不假设服务名/目录结构**）|
| 上下文 | `get_log_context` | 含续行；单行截断 500 字符 |
| 栈解析 | `parse_stack_trace` | 任意行 → 向上回溯异常行 → 向下收栈；返回 `resolved_from_line` |
| 事件链 | `correlate_events` | 按 traceId 聚合所有扫描文件的事件（时间排序）；返回出现事件的文件；不假设服务名 |
| 读原文 | `Read` | 需要人工核对时 |

- **禁止**修改日志文件；禁止编造未观测事件；
- 未命中（`no_match`）不是错误；traceId 缺失时明确"无法关联"并改用关键字检索。

## 8. 分析深度与停止条件

- 事件链追溯到根因服务/最早失败点即停（不无限回溯）；
- 同一结论重复证据 3 次无新增 → 停止并声明；
- 证据不足如实降级（`partial`/`failed`）。

## 9. 红线（违反即结论无效）

1. 把首异常直接表述为根因（无代码/配置/数据证据）；
2. 隐瞒日志缺失/采样/时间偏差；
3. 编造未观测的事件或行号；
4. 修改日志文件（本 Skill 只读）；
5. 用字符串比较时间窗或忽略续行继承（工具已处理，引用时不得歪曲）。
